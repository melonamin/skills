# Landing page

## Brief and foundation

Read the request and existing project. Establish audience, product value, primary action, supported claims, required sections, brand constraints, and delivery target from available context. Ask only about missing facts that materially change the result. For a planning request, deliver the complete brief and open decisions together; use an interview only when requested.

Use the existing stack and design system. For a new project, choose the smallest suitable stack; read [tech stack setup](references/tech-stack-setup.md) only for relevant setup or SEO details, treating its examples as optional and checking current tool syntax. For hosted or standalone HTML deliverables, use Spot and its current platform instructions.

Write realistic copy before refining layout. Read [B2B copy checklist](references/b2b-copy-checklist.md) when drafting or reviewing B2B copy. Keep claims grounded; mark missing evidence instead of inventing logos, testimonials, or metrics.

## Design and implementation

Apply frontend-design. Choose one coherent direction by default. Produce two or three variants when requested or when a consequential unresolved visual choice benefits from comparison. Keep comparison copy and scope consistent. Use available agent tools only when delegation is authorized; no named provider-specific subagent is required.

Build a responsive working page with functional calls to action, semantic structure, accessible navigation, and appropriate metadata. Implement within the authorized scope; commits, publication, and deployment follow the user's authorization, not phase checkpoints.

## Validate and refine

Run project checks. Use available browser tooling (read agent-browser when using its CLI) to inspect narrow and wide viewports and exercise navigation, forms, and calls to action. Fix observed defects, then recheck affected views. Use web-perf when a performance audit is part of the task; do not assume browser automation supplies Lighthouse.

Incorporate feedback into concrete layout, copy, or interaction changes. Report completed work, actual verification, and remaining content or integration decisions. Do not wait for approval between routine implementation phases.
